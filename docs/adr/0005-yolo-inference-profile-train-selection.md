# YOLO inference profile train selection

Status: accepted

YOLO whole-section inference uses SAHI sliding windows plus per-slice Ultralytics detection. Hyperparameters for slice-merge postprocess (`postprocess_type`, `match_metric`, `match_threshold`), minimum **score** (`conf`), and `mask_threshold` were previously hard-coded (GREEDYNMM, IOS, 0.5, 0.25, SAHI default 0.5) and not train-selected. ADR 0003 fixed window geometry and rejected **per-variant** inference tuning on test so **variant test ranking** is not confounded by modality-specific settings. We still need a defensible way to choose YOLO inference settings before held-out test.

We introduce **YOLO inference profile** selection on the **train** section: a **full factorial grid** over all five knobs (search space in `configs/yolo_inference_profile_tune.yaml`) that maximizes mean whole-section train **AJI** on the canonical **instance prediction set** (after **score merge** at predict — [ADR 0004](0004-yolo-score-merge-at-predict.md)), averaged across all registry variants (each variant uses its own `best.pt`). Pre-merge metrics (e.g. proposal counts, optional mask AP on overlapping proposals) are diagnostic only, not the selection objective. The winning profile is **one shared set of values for all variants**, promoted into `configs/test_inference.yaml` and **committed to git**; scratch tune runs retain audit tables under `runs/yolo_inference_profile_tune/<run_id>/grid/`. Re-run profile selection when train labels or YOLO weights change materially, not after every single-variant training job. Patch test jobs use `conf` and `mask_threshold` from the same recipe; SAHI merge keys apply to whole-section predict only.

**Slice-boundary duplicate** (non-overlapping halves of one grain across tiles) is not expected to be fixed by this tuning; it remains an accepted limitation of the YOLO system.

**Considered options:** Per-variant profiles on train (rejected — confounds **variant test ranking** on test); two-stage coordinate search over merge then `conf`/`mask_threshold` (superseded — can miss knob interactions; with **tiled detector proposal** reuse, detector cost is ~one pass per distinct `(conf, mask_threshold)` per variant, so full grid eval cost dominates); primary objective on overlapping **detector proposals** (rejected — not the deployed system after ADR 0004); Bayesian search (deferred); scratch-only winning values without git commit (rejected — weak reproducibility).

**Consequences:** Depends on ADR 0004 implementation before tune jobs. Extend `configs/test_inference.yaml` and `test_inference` loader with YOLO profile fields; wire `yolo.predict` and SLURM whole/patch test scripts; add `SLURM/yolo` train whole tune step and factorial grid config. [ADR 0003](0003-test-evaluation-policy.md) documents how the promoted profile fits the test inference recipe. U-Net **extraction profile** stays per-model (watershed JSON), unchanged.

**Mask threshold** is a detector binarization cutoff: whole-section predict passes it into SAHI `AutoDetectionModel`; patch predict passes it into Ultralytics `predict`. Grid search over `mask_threshold` affects whole-section AJI via the detector, not via a second threshold when encoding the **instance prediction set** from an already-binarized `bool_mask` plane.

**Profile promotion** copies the grid winner (`grid/winner.json`, all five profile knobs) into `configs/test_inference.yaml` for git commit and held-out test. Promotion rewrites the five YOLO profile scalars in the recipe file text so comments and unrelated keys are preserved (structured YAML round-trip deferred).

**Tiled proposal cache (profile tune only):** Grid points that share detector inputs (variant `best.pt`, train whole **sample id**, **test inference recipe** window geometry, `conf`, **mask threshold**) reuse persisted **tiled detector proposals** (pickle + JSON sidecar with `schema_version` and strict fingerprint: weights SHA-256, recipe window hash, detector knobs, variant, sample id) under `runs/yolo_inference_profile_tune/<run_id>/_work/`. Train manifests are staged once per variant. On cache hit each scoring task re-runs only SAHI slice-merge and **score merge** to a **merged instance view** for **profile selection scoring** (see below). Held-out `yolo.predict` is unchanged (no cache CLI). Slice inference is shared with `predict.py` via extracted internals, not duplicated in tune.

**Profile selection ground truth cache:** After detector jobs finish, one CPU job rasterizes per-variant train ground truth to a fingerprinted **profile selection ground truth cache** (merged instance view per variant from `train_labels.gpkg`). All candidate scoring tasks read this cache; GT does not depend on **tiled detector proposals**.

**Profile selection scoring:** Grid scoring computes train **AJI** from **tiled detector proposals** through slice-merge and **score merge** to a **merged instance view**, compared against the GT cache. It does not require writing an **instance prediction set** for every grid point. Automated parity with the canonical eval path is **AJI-only** on fixed fixtures (tight float tolerance, at least one grid point per registry variant). Held-out test still uses full predict and persisted **instance prediction set** artifacts.

**Tune job audit and resume:** Each grid candidate task writes one **profile selection result row** (`grid/rows/{candidate_id}.json`) with per-variant **AJI**, mean **AJI**, knob values, and input fingerprints. A finalize job (`afterok` on the candidate array) merges rows into `grid/results.csv` and writes `grid/winner.json` (or recomputes the winner from the CSV). A candidate task skips when its row exists and fingerprints still match (grid spec, GT cache, weights, proposal caches). `NO_RESUME` clears row sidecars and resubmits scoring; valid **tiled detector proposals** remain reused.

**Cluster orchestration:** `submit_inference_profile_tune.sh` assigns `OUTPUT_DIR` (`runs/yolo_inference_profile_tune/<run_id>/`) before submission, then: (1) one GPU job per `(variant, conf, mask_threshold)` via `yolo.profile_tune_detector` (tiled-proposal cache only; 32G); (2) after all detectors succeed, one CPU GT-cache job; (3) a SLURM array of one CPU job per grid candidate (all tasks submitted together; scheduler fair-share controls overlap) via `yolo.profile_tune_candidate` (or equivalent), each scoring all registry variants (32G, 8 CPUs, 4h); (4) one CPU finalize job after the array. Failed detector or GT-cache jobs block downstream work until resubmitted. The former single-job `yolo.profile_tune_grid` coordinator is removed.
