# GPKG ground-truth rasterization

Status: accepted

Whole-section train labels (`train_labels.gpkg`) drive **profile selection** and instance evaluation via a dense **merged instance view** (per-pixel instance ids). The first implementation decoded each COCO annotation with `pycocotools` at full image resolution. On the train mosaic (~52k×10k px, ~2.7k grains) that cost hours per tune run and was unsuitable for a CPU cache job. Preprocessing already rasterizes the same GPKG with OpenCV `fillPoly` for U-Net semantic TIFFs (`gpkg_to_raster.py`), but those outputs are three-class semantic masks with boundary erosion—not the instance-id layout metrics require.

We adopt **OpenCV polygon painting in `common` as the single canonical** GPKG → **merged instance view** path for all production callers (`evaluate_instances`, U-Net watershed tuning on GPKG, **profile selection ground truth cache**). The painter reuses today’s topology rules (iterate polygon parts, clip to the image frame, assign sequential instance ids, paint in ascending id order so later grains overwrite overlaps) but draws **exterior rings only** with `cv2.fillPoly` after **`np.rint`** vertex discretization. Interior rings are not carved: the overlap-split preprocessing pipeline already delivers hole-free polygons. We do **not** reuse `gpkg_to_raster` semantics (no boundary-width classes, no semantic 1/2/0 encoding).

**Profile selection ground truth cache** layout changes: one raster per tune run under `_work/gt_cache/train/` (`instance_map.npz` + `fingerprint.json`), fingerprinted on `train_labels.gpkg` (SHA-256), **sample id**, width, and height—not on input variant. All registry variants share the same label geometry; channel-specific train TIFFs only anchor predictions; each **profile selection** candidate task loads this cache once per job ([ADR 0007](0007-profile-selection-proposal-cache-and-scoring.md)). The GT-cache SLURM job syncs `src/common` only (no YOLO/torch), copies the GPKG to `$TMPDIR` before rasterizing, and writes the canonical cache back to scratch. The GT-cache job logs phase timings (e.g. copy GPKG, rasterize, write `npz`) for operability on train-scale mosaics.

**Considered options:** Keep `pycocotools` as production canonical with a permanent test reference (rejected—slow, and we explicitly chose OpenCV as the definition of GT pixels); per-variant `gt_cache/{variant}/` with four raster passes (rejected—redundant for shared geometry); AJI-only fixture gate without a golden map (rejected after grill—grid selection is sensitive to small GT shifts); optional `common[opencv]` extra (rejected—eval and tune must not depend on remembering an extra); read preprocessing `train_labels.tif` for profile tune (rejected—wrong semantics).

**Consequences:** **Hard break** for in-flight `runs/yolo_inference_profile_tune/*` jobs: implement together with [ADR 0007](0007-profile-selection-proposal-cache-and-scoring.md), delete the entire tune run directory, submit a new `RUN_ID`, and rerun detector → GT-cache → candidate array (v1 proposal caches are not reused). **Profile selection result row** GT fingerprints change (`variant` removed; cache schema version bumped)—stale rows are not resumed. Grid winners from runs scored with the old rasterizer are not guaranteed comparable to reruns after this ADR. Remove the GT code path that called `gt_annotations_to_instance_map` on vector annotations; keep `pycocotools` only where predictions (not GPKG GT) require mask decode. Add `opencv-python-headless` to `common` dependencies. Lock behavior with a committed micro-GPKG under `src/common/tests/fixtures/` plus a golden `instance_map.npz` and a small regen script when the fixture is intentionally updated. [ADR 0005](0005-yolo-inference-profile-train-selection.md) orchestration (detector cache → GT cache → candidate array) is unchanged; the GT-cache bullet there is superseded on **layout and rasterization** by this ADR. Domain terms: `CONTEXT.md` (**Profile selection ground truth cache**, **Merged instance view**).
