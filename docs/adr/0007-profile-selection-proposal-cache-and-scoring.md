# Profile selection proposal cache and scoring

Status: accepted

**Profile selection** reuses persisted **tiled detector proposals** so grid tasks rerun only SAHI slice-merge and **score merge** per candidate ([ADR 0005](0005-yolo-inference-profile-train-selection.md)). The first cache (`schema_version` 1) pickled SAHI `ObjectPrediction` graphs whose `bool_mask` planes were dense **full-section** arrays (~520M pixels each, mostly empty). **Profile selection scoring** then routed those proposals through the same **instance prediction set** encode → **score merge** → rasterize path as held-out eval, but on thousands of overlapping pre-merge masks. That made candidate jobs take hours per variant while SAHI merge (~tens of seconds) and eval-time AJI (minutes) stayed fast.

We adopt **tiled detector proposals `schema_version` 2**: a list of compact neutral records per `(variant, conf, mask_threshold)` cache—each record carries **score**, full-image **bbox**, and **crop-local COCO RLE** plus **`offset_y` / `offset_x`**, with full-section **height** and **width** in cache metadata. The detector job writes v2 after sliced inference (crop from each shifted detection); no SAHI types on disk. **Profile selection scoring** loads v2 records, adapts them for `merge_sliced_object_predictions` (SAHI slice-merge unchanged), then **score merge** paints crops into one in-memory **merged instance view** by ascending **score** (shared helper in `common`) and runs `compute_aji`. It does **not** build a transient **instance prediction set** per grid point. Each **profile selection** candidate task loads the shared **profile selection ground truth cache** ([ADR 0006](0006-gpkg-ground-truth-rasterization.md)) **once** and reuses the same train **merged instance view** for all registry variants—label geometry is identical across variants. Held-out `yolo.predict` and `evaluate_instances` are unchanged.

**Observability:** Candidate and scoring code log **phase timings** at fine granularity (e.g. load proposals, slice-merge, score merge, AJI; per-variant sub-phases where useful) so cluster logs show where walltime goes without a profiler. One summary line per variant remains; timings are seconds with one decimal place.

**Considered options:** Scoring-only fast path on v1 full-canvas pickles (rejected—still decodes huge planes; user chose full cache/scoring fix); bbox-dense crops in pickle (rejected—larger than RLE for large grains); full-image RLE per proposal (rejected—defeats crop-local storage); in-house slice-merge without SAHI (rejected—parity risk; merge is not the bottleneck); keeping 8 CPUs on candidate jobs (rejected for v1 post-fix—scoring is single-threaded; use 1 CPU with 4h walltime until timings are known).

**Parity:** (1) v2 **profile selection scoring** must match legacy v1 scoring **AJI** on fixed fixtures with identical GT (tight tolerance); remove legacy scoring after gate. (2) OpenCV GT golden **merged instance view** / AJI is separate ([ADR 0006](0006-gpkg-ground-truth-rasterization.md)). **Profile selection result row** fingerprints include proposal `schema_version` 2 and the ADR 0006 GT cache layout; stale rows do not resume.

**Salvage (with ADR 0006):** Implement both ADRs in one batch. Delete the entire `runs/yolo_inference_profile_tune/<run_id>/` directory for in-flight runs and submit a **new** `RUN_ID` (do not `--skip-detectors` from the old run). Rerun detector array → GT cache → candidate array → finalize. Grid winners from runs before this ADR are not comparable to reruns.

**Consequences:** Bump `TILED_PROPOSAL_CACHE_SCHEMA_VERSION` to 2; reject v1 on load. Refactor `profile_tune_candidate` so `score_profile_selection_candidate` loads GT once per task, not inside the per-variant loop (avoids four redundant ~2 GB decompressions per candidate on train). Finer phase timing logs on candidate and scoring paths. Cross-link [ADR 0005](0005-yolo-inference-profile-train-selection.md) orchestration (unchanged job graph); supersede ADR 0005’s v1 pickle description for on-disk proposals. Candidate SLURM: 32G, **1 CPU**, **4h** for the first post-fix grid. Optional **instance prediction set** materialization only for the grid winner or explicit audit samples—not per candidate×variant. Domain terms: `CONTEXT.md` (**Tiled detector proposals**, **Profile selection scoring**).
