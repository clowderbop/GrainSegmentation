# PQ headline instance evaluation

Status: accepted

The scientific target is **individual grain instance recovery** on whole sandstone thin sections: each annotated grain should be recovered as a separate predicted instance, with both object detection and mask quality reflected in the evaluation. The previous held-out headline used whole-section **AJI** with **F1@IoU50** alongside (ADR 0003), and YOLO **profile selection** maximized mean train AJI across input variants (ADR 0005). A YOLO inference profile refinement showed that maximizing AJI can prefer lower confidence and weaker merging settings that raise area-overlap score while producing many more predicted instances and worse object-level behavior. This makes AJI a poor single headline for the project’s stated instance-recovery target.

We use **whole-section Panoptic Quality (PQ)** as the headline metric for **variant test ranking** and **model test comparison**. PQ is computed on the whole-section **merged instance view** with the standard strict IoU > 0.5 match convention. Reports include the companion decomposition **DQ** (detection quality) and **SQ** (segmentation quality), plus precision, recall, and F1 at IoU50 and IoU75; mean F1 over IoU50:95; predicted instance count; ground-truth instance count; predicted/ground-truth instance ratio; and **AJI+**. Thresholded matching diagnostics use the same strict IoU > threshold convention as PQ. **AJI+** remains a supporting microscopy-style overlap diagnostic, not the headline.

The standard **instance metric bundle** is computed for every instance evaluation whenever the producer artifacts support it, across train/test, patch/whole-section, and YOLO/U-Net. The bundle computes PQ on the evaluated sample unit: **whole-section PQ** is reserved for headline/ranking/profile-selection contexts, while patch evaluations compute patch-level PQ as diagnostics. Patch-level metrics are supporting diagnostics for whether **sliding window** inference changes performance; they do not influence held-out ranking, locked grid design, or profile selection.

Train-side selection steps use the same whole-section PQ objective as held-out reporting. YOLO **profile selection** maximizes mean train whole-section PQ across registry variants, not mean AJI. U-Net watershed tuning selects per-model **U-Net extraction profile** settings by train whole-section PQ, and the CC-vs-tuned-watershed comparison chooses the train winner by whole-section PQ. Candidate audit rows record mean and per-variant PQ plus the full diagnostic bundle and input fingerprints where applicable. The shared YOLO inference profile remains train-selected and promoted into the **test inference recipe** before held-out evaluation; per-variant test inference settings remain out of scope. U-Net extraction profiles remain per checkpoint.

AP/mAP metrics are outside the instance metric bundle. They are computed only by Ultralytics val on patch data as optional YOLO detector diagnostics. Whole-section Mask AP on canonical YOLO instance prediction sets is not part of the standard evaluation policy and is not shown in main result figures. AP/mAP must not be used for **variant test ranking** or **model test comparison**.

**Considered options:** Keep AJI as headline (rejected — area-aggregated overlap can improve while duplicate or split instance behavior worsens); switch to AJI+ as headline (rejected — improves unique pairing but remains area-aggregated and does not directly separate detection from mask quality); use F1@IoU50 as headline (rejected as too coarse for mask quality, but retained as a required diagnostic); use COCO-style AP/mAP as headline (rejected — score-ranked and YOLO-centric, not comparable to U-Net extracted instances); patch metrics as ranking inputs (rejected — patch crops are not the deployment unit and miss whole-section stitching/merge behavior).

**Consequences:** ADR 0003 and ADR 0005 are superseded for metric headline and profile-selection objective. Evaluation code, reporting, YOLO profile-tune scoring, U-Net watershed tuning, and CC-vs-watershed comparison need to add PQ/DQ/SQ, AJI+, strict-threshold P/R/F diagnostics, instance-count ratio, and train-PQ candidate selection. Existing AJI-selected YOLO profile and watershed runs are useful audit evidence but should not be promoted as final test settings under this policy.
