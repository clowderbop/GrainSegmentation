# Profile selection proposal cache and scoring

Status: accepted

**Profile selection** reuses persisted **tiled detector proposals** so grid tasks rerun only SAHI slice-merge and **score merge** per candidate ([ADR 0005](0005-yolo-inference-profile-train-selection.md)). The first cache (`schema_version` 1) pickled SAHI `ObjectPrediction` graphs whose `bool_mask` planes were dense **full-section** arrays (~520M pixels each, mostly empty). **Profile selection scoring** then routed those proposals through the same **instance prediction set** encode → **score merge** → rasterize path as held-out eval, but on thousands of overlapping pre-merge masks. That made candidate jobs take hours per variant while SAHI merge (~tens of seconds) and eval-time AJI (minutes) stayed fast.

We adopt **tiled detector proposals `schema_version` 2**: a list of compact neutral records per `(variant, conf, mask_threshold)` cache—each record carries **score**, full-image **bbox**, and **crop-local COCO RLE** plus **`offset_y` / `offset_x`**, with full-section **height** and **width** in cache metadata. The detector job writes v2 after sliced inference (crop from each shifted detection); no SAHI types on disk. **Profile selection scoring** loads v2 records, adapts them for `merge_sliced_object_predictions` (SAHI slice-merge unchanged), then **score merge** paints crops into one in-memory **merged instance view** by ascending **score** (shared helper in `common`) and runs `compute_aji`. It does **not** build a transient **instance prediction set** per grid point. Each **profile selection** candidate task loads the shared **profile selection ground truth cache** ([ADR 0006](0006-gpkg-ground-truth-rasterization.md)) **once** and reuses the same train **merged instance view** for all registry variants—label geometry is identical across variants. Held-out `yolo.predict` and `evaluate_instances` are unchanged.

**Observability:** Candidate and scoring code log **phase timings** at fine granularity (e.g. load proposals, slice-merge, score merge, AJI; per-variant sub-phases where useful) so cluster logs show where walltime goes without a profiler. One summary line per variant remains; timings are seconds with one decimal place. The detector job logs one summary line after collecting **tiled detector proposals** (slice count, proposal count, encode seconds).

**Implementation note (detector encode):** SAHI `Mask.bool_mask` decodes segmentation to the `full_shape` stored on the object. Calling `convert_original_predictions(..., full_shape=[whole height, whole width])` and then reading masks (or post-hoc “encode shifted predictions”) materializes ~520M-pixel planes per detection and regresses `yolo_prof_det` walltime. The profile-tune detector path must use a dedicated slice-loop collector: per slice, `convert_original_predictions(shift_amount=[tlx, tly], full_shape=None)` so masks stay tile-sized; build v2 records from a tight tile mask crop plus whole-image `offset_y` / `offset_x` (`tly`/`tlx` + crop origin); never call `get_shifted_object_prediction()` on that path. Held-out **predict** keeps whole-section `full_shape` and shifted SAHI objects for slice-merge. Do not reintroduce a post-SAHI encoder that upsamples to full section.

**Implementation note (scoring adapter):** v2 records must not be expanded into a list of full-section `bool_mask` planes (~520M pixels each) before slice-merge. That regresses the v1 pickle failure mode and OOMs candidate jobs at modest SLURM memory limits (~60 masks × ~500 MB ≈ 32 GB). **Profile selection scoring** adapts each record to SAHI-shaped objects with **crop-local** `bool_mask` (decode crop RLE once per record) and whole-image **bbox** / **score**; SAHI slice-merge stays unchanged (GREEDYNMM/NMM match on boxes; mask union only on merge pairs). **Score merge** paints one merged detection at a time into the **merged instance view**, using **bbox-local** rasterization (crop placement or `fillPoly` on the detection window) rather than SAHI `Mask.bool_mask` on the full section (~520M pixels per call). Full-section RLE decode-then-crop is allowed as a single bounded plane per detection. Do not call `full_binary_mask_from_tiled_proposal_record` (or equivalent) for every record up front. Parity tests still compare this path to the **instance prediction set** encode → score merge → rasterize reference (`profile_tune_legacy_scoring`) until that gate is removed.

**Considered options:** Scoring-only fast path on v1 full-canvas pickles (rejected—still decodes huge planes; user chose full cache/scoring fix); bbox-dense crops in pickle (rejected—larger than RLE for large grains); full-image RLE per proposal (rejected—defeats crop-local storage); in-house slice-merge without SAHI (rejected—parity risk; merge is not the bottleneck); keeping 8 CPUs on candidate jobs (rejected for v1 post-fix—scoring is single-threaded); **4h** candidate walltime (insufficient on train after adapter fix—~70 min score-merge per variant × 4 before bbox-local paint; raised to **8h** interim until post-fix cluster timings confirm margin).

**Parity:** (1) v2 **profile selection scoring** must match legacy v1 scoring **AJI** on fixed fixtures with identical GT (tight tolerance); remove legacy scoring after gate. (2) Add at least one **overlapping** fixture (merge pairs exercised with crop-local masks), not only disjoint v2-cache parity—slice-merge mask union is the gap disjoint tests skip. (3) OpenCV GT golden **merged instance view** / AJI is separate ([ADR 0006](0006-gpkg-ground-truth-rasterization.md)). **Profile selection result row** fingerprints include proposal `schema_version` 2 and the ADR 0006 GT cache layout; stale rows do not resume. A scoring-only code fix does not bump row fingerprints; clear partial `grid/rows/` or use `NO_RESUME=1` when re-running candidates after an OOM or aborted array.

**Consequences:** Bump `TILED_PROPOSAL_CACHE_SCHEMA_VERSION` to 2; reject v1 on load. In-flight tune runs from before this ADR (with [ADR 0006](0006-gpkg-ground-truth-rasterization.md)) must not reuse `_work/` or partial rows—delete the run directory and submit a new `RUN_ID`; grid winners from pre-change runs are not comparable to reruns. With unchanged v2 proposal and GT caches in the same `OUTPUT_DIR`, `--skip-detectors` may skip the detector array when re-running candidates (cluster steps: [`docs/runbooks/yolo.md`](../runbooks/yolo.md#profile-selection)). Refactor `profile_tune_candidate` so `score_profile_selection_candidate` loads GT once per task, not inside the per-variant loop (avoids four redundant ~2 GB decompressions per candidate on train). Fix scoring adapter per implementation note above. Finer phase timing logs on candidate and scoring paths. Cross-link [ADR 0005](0005-yolo-inference-profile-train-selection.md) orchestration; supersede ADR 0005’s v1 pickle description for on-disk proposals. Candidate SLURM: **50G** (interim headroom after adapter fix; lower when cluster timings show margin), **1 CPU**, **8h** (interim; was 4h before train timings and bbox-local score-merge fix). Optional **instance prediction set** materialization only for the grid winner or explicit audit samples—not per candidate×variant. Domain terms: `CONTEXT.md` (**Tiled detector proposals**, **Profile selection scoring**).
